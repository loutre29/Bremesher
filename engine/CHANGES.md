## Deviations

### WP-00 (aq_core + workspace), 2026-10-29

1. **rust-toolchain.toml uses `channel = "stable"`, not `"1.99"`.** The only toolchain installed on this machine is `stable` = rustc 1.99.1. A channel named `1.99` makes rustup download and install a second toolchain into the user profile, which is outside the project folder. The minimum version is pinned instead with `rust-version = "1.99"` in `[workspace.package]`. The target `x86_64-pc-windows-msvc` is listed as required.

2. **C8: delta is reduced modulo 2pi into (-pi, pi].** DESIGN writes `delta = theta_g - theta_f - kappa - p pi/2` "not wrapped", and also says that a freshly rounded delta lies in [-pi/4, pi/4]. Both cannot hold, because p is stored mod 4: with `x = (theta_g - theta_f - kappa)/(pi/2) = -1.0` the rounded matching is `p = 3`, and the unreduced formula gives `-2pi` instead of 0, which shifts index4 by 4. `aq_core::cross::delta_edge` therefore returns `wrap_pi(theta_g - theta_f - kappa - p pi/2)`: it picks the representative of p nearest the actual rotation. Fresh deltas are in [-pi/4, pi/4] as specified, edited deltas may be larger, and `delta[twin] = -delta` stays exact. **Consequence for aq_field:** a matching edit is only meaningful while the true rotation across the edge stays inside (-pi, pi) (always true after one edit of a fresh edge, |delta| <= 3pi/4). Every crate must compute delta through `delta_edge` / `delta_from_p` / `matching_from_theta`.

3. **C12: a raw branch k is the combed branch `(k - c_f) mod 4`, not `(k + c_f) mod 4`.** With `theta' = theta + c_f pi/2` (the primary definition, and the one consistent with `r = (p + c_g - c_f) mod 4`), raw branch k has the direction `theta + k pi/2 = theta' + (k - c_f) pi/2`. The test `combing_and_families` pins it. Both formulas agree mod 2, so every family (U/V) decision written in DESIGN (aq_param loop rows, C13) is unaffected. Use `aq_core::cross::raw_to_combed_branch` and `combed_to_raw_branch`.

4. **6.1 transport test "planar jittered grid: |kappa| < 1e-12" is tested in its intended form.** With C4 every face has its own frame (`e1 = normalize(p1 - p0)`), so on a plane `kappa[he] = beta_f - beta_g` (beta = global angle of e1), which is not 0. The test checks that flat transport is trivial: `wrap_pi(kappa - (beta_f - beta_g)) < 1e-12` for every halfedge, a global direction keeps its global angle across every edge, and the holonomy around every interior vertex is 0 within 1e-12.

5. **Errors raised inside aq_core carry `Stage::Engine`.** aq_core cannot know which stage calls it. Callers restamp with `AqError::at(stage)` (for example `.map_err(|e| e.at(Stage::Field))`). `Ctl::check` uses the stage last published with `Ctl::progress`.

6. **`Stage` has explicit discriminants 0..13 in the order of DESIGN 5** (Ingest = 0 ... Ffi = 13). These are the values written to `AqControl.stage`. `Stage`, `ErrKind`, `FeatureKind`, `NodeKind` and `ArcKind` derive more traits than listed (Debug, Eq, Ord, Hash, Default where sensible).

7. **aq_ffi uses `crate-type = ["cdylib", "rlib"]`** with `[lib] name = "autoquad_engine"`, so WP-05 can call the exported functions from Rust tests. The DLL is still `autoquad_engine.dll`. WP-05 owns the file and may drop `rlib`. aq_ffi and aq_cli also depend on aq_core directly (for the shared types), and aq_engine also on aq_linalg and aq_io.

8. **faer is imported with `default-features = false`** and the features `std`, `rayon`, `sparse-linalg` (sparse Cholesky with AMD, dense LU and eigen are included). Its default features pull the `rand` crates and `npyz`, which 3.3 forbids.

9. **Bvh.** `Bvh::build(m) -> Self` is infallible as specified; on an index out of range or a failed allocation it returns an empty BVH. `Bvh::try_build` returns `Result` (`Budget`, `InvalidInput`) for callers that need it. The `f64` returned by `closest` is the Euclidean distance (not squared). Ties are broken by the lowest face id. For an empty BVH, `closest` returns face `NONE`, the query point and an infinite distance. `Bvh::closest_among` gives the brute-force reference.

10. **Projector walk, precise rule.** Ring r is the set of faces sharing a vertex with ring r-1 (ring 0 = the hint face). The walk converges when the closest face of rings 0..r already lies in rings 0..r-1 (or when the component is exhausted); it fails after 3 rings. A converged result is accepted when `n_face . normalize(n_ref) > 0.5`, otherwise the BVH closest point is tested the same way, otherwise `None`. A zero or non-finite `n_ref` fails the test. `Projector::new(mesh, topo, frames, bvh)` builds it (fields are public), and `Projector::walk` exposes the walk alone.

11. **validate() signatures.** DESIGN gives `validate(&self, ...)`. The frozen signatures are:
    - `TriMesh::validate(&self)`, `QuadMesh::validate(&self)` (also checks that every directed edge is used once), `Topology::validate(&self, m)`, `Frames::validate(&self, m, t)`;
    - `CrossField::validate(&self, m, t, fr)` (twin rules, delta consistent with theta and p within 1e-9, index4 recomputed, Poincare-Hopf per component);
    - `FeatureSet::validate(&self, m, t)` (boundary halfedges must carry Boundary or Symmetry, per 6.4 step 6);
    - `CurvField::validate(&self, n_faces, n_verts)`, `SizeField::validate(&self, fr, n_verts)` (n_pred within 1e-6 relative);
    - `CutGraph::validate(&self, m, t, Option<&CrossField>)`, `LoopCand::validate(&self, m, t)`, `SurfacePoint::validate(&self, n_faces)`;
    - `SeamlessParam::validate(&self, m, t)` (dyadic, bound, transitions exact at both endpoints of every interior halfedge, iso exactness from `he_family`; a bound violation is `Numerical`, the rest `Invariant`);
    - `TMesh::validate(&self)`, `QComb::validate(&self, &TMesh)`, `Layout::validate(&self, n_proxy_faces)`, `LayoutHealth::validate`, `ParamReport::validate`, `Transition::validate`.
    "Bitwise" equality of uv and transitions is checked with f64 `==` (so +0.0 equals -0.0); `rot`, `Transition::inverse` and `Transition::compose` normalize zero results to +0.0, so `compose(T, T.inverse())` is the identity bit for bit.

12. **`LayoutHealth` was not defined in DESIGN.** It is `{ per_patch: Vec<f64>, mean, max, frac_above }` with `frac_above` = fraction of patches with m_P > 0.1, built by `LayoutHealth::from_sides(&[[l0, l1, l2, l3]])`.

13. **API additions (non-breaking, all in aq_core):** `cross::{delta_edge, matching_edge, index4_vertex, poincare_hopf, map_branch, branch_dir, comb_theta, comb_matching, raw_to_combed_branch, combed_to_raw_branch, jacobian, det2, fold_eps, folded_faces}`, `CrossField::{from_theta, cones}`, `Transition::{IDENTITY, apply_vec, is_identity}`, `Topology::{ccw_out, cw_out, twin_of, is_boundary_he, valence, valence_faces, find_he, n_boundary_loops}`, `Frames::{angle_sum, dir_at, face_coords}`, `FeatureSet::{new, is_chain_he}`, `FeatureKind::from_u8`, `TMesh::{arc_walk, arc_occurrences, patch_corners}`, `SeamlessParam::he_uv`, `param::FAMILY_NONE`, `SizeField::predicted_count`, `SurfacePoint::position`, `QuadMesh::{new, face, push_face, is_all_quads}`, `TriMesh::{tri_pos, face_cross, face_normal, face_area, total_area, bbox, bbox_diag}`, `Ctl::{new, is_cancelled, stage, deadline}`, `CtlState` (owned atomics for the CLI and tests), `AqError::{new, core, at, ...}`, modules `tol` (C14 constants, `snap_dyadic`, `is_dyadic`, `clamp_weight`, `is_zero_area`), `exact` (orient2d/orient3d wrappers of `robust`), `math` (vector helpers), `alloc` (`try_vec`, `try_with_capacity`, `try_reserve` returning `Budget`), `bvh::closest_on_triangle`.

14. **`Topology::build` also rejects** an index out of range or a repeated index in a face (`InvalidInput`), a vertex with two outgoing boundary halfedges or whose fan does not reach all its outgoing halfedges (`Topology`, a non-manifold vertex). Isolated vertices are allowed (`vert_he = NONE`, in no component). Boundary loops start at their lowest halfedge id and are sorted by it; components are numbered by their lowest face.

15. **Tag `core-v1`.** The project folder is not a git repository, so no tag was created. The aq_core API above is frozen as of this entry; later changes go through "Core change requests".

### WP-01 (aq_io + aq_eval), 2026-10-29

DESIGN 6.15 gives the aq_eval signatures but leaves several rules open. The choices below are now the contract of these crates.

1. **aq_io API** (DESIGN gives no signatures): `parse_obj(&str)`, `read_obj(path) -> ObjData` (raw polygons, `skipped_faces`), `read_obj_tri` (fan-triangulated from the first vertex), `read_obj_poly` (polygons kept, vflag and face_comp 0), `write_tri_obj` / `write_quad_obj` (to any `Write`), `write_obj_tri` / `write_obj_quad` / `write_file` (to a path, parent folders created). Read errors are `InvalidInput` stamped `Stage::Ingest`, write errors `Internal` stamped `Stage::Engine`. The reader accepts NaN and Inf coordinates and degenerate faces unchanged (ingest must see them), and drops faces with fewer than 3 vertices (counted in `skipped_faces`). Coordinates are written with Rust's shortest round-trip format, so write then read is bit-exact.
2. **Dumps**: `dump_proxy(w, mesh, Option<&FeatureSet>)`, `dump_field(w, mesh, frames, theta, arm)` (u and v segments per face, `arm <= 0` gives 0.4 sqrt(area)), `dump_cones(w, pos, cones)`, `dump_cut(w, mesh, &CutGraph)`, `dump_param(w, mesh, &SeamlessParam)` (vt per corner, folded faces in their own group), `dump_layout(w, &Layout)`, `dump_quant(w, &TMesh, Option<&[u32]> n per arc, Option<&QComb>)` (`QuantResult` lives in aq_quantize, which aq_io must not depend on, so the dump takes the arc lengths and the QComb), `dump_patches(w, &QuadMesh, quad_patch)`, and `DumpDir` for the standard file names. Dumps skip out-of-range entries instead of failing.
3. **quad_stats** returns unrounded values; `QuadStats::py_rounded()` and `to_py_json()` reproduce the script's rounding (`round(x, n)`, done with `{:.n}`) and key names. Faces with a bad CSR range or an out-of-range vertex are skipped. An edgeless mesh gives edge_cv 0 (the script divides by zero there). Parity fixtures for all 11 baselines (not only torus and retopo_a) are in `crates/aq_eval/tests/fixtures/stats_*.json`, produced by `crates/aq_eval/tests/fixtures/gen_stats_fixtures.py`, which imports `tools/quad_stats.py` and records the script's dict ("py") and the same dict with `round` disabled ("raw"). The test checks raw within 1e-6 and the rounded dict exactly.
4. **hausdorff**: polygons are measured through their fan triangulation from the first vertex. The samples are every used vertex plus `samples_per_face` R2 low-discrepancy points per triangle. Max is over all samples. The mean is area-weighted over the triangle samples, or the plain vertex mean when `samples_per_face == 0`. Results are in input units. `Hausdorff::scaled(1/h)` converts to h, and `symmetric()` gives the max of both sides. An empty source side gives 0, and an empty target side gives infinity. Fixed chunking makes the result bit-identical for any thread count, which is tested. Added `vertex_distance(q, input) -> (max, mean)` for the gate "distance from output vertices to the input".
5. **loop_closure**:
    - Lines run straight through regular interior vertices (valence 4 with a closed fan of 4 clean edges).
    - Boundary edges continue along the boundary through valence-3 boundary vertices, so the boundary rings of an open cylinder count as closed loops. A line stops at a corner (b2) and at any irregular or non-manifold vertex.
    - "Mean direction" is read as the length-weighted mean of |cos(edge, axis)|. A closed loop's mean edge vector is zero, so a plain mean would not work. Lines with a value below 0.3 count as circumferential.
    - Helix suspect: a counted line whose azimuth about the axis completes a full turn with an axial drift above 0.5 h. The axis passes through the mean used vertex, and h is the mean edge length, because the signature carries no h. Drift is measured between successive 2pi crossings.
    - `closed_frac` is 0 when no line is counted.
6. **bisect**:
    - A vertex within `1e-9 * bbox_diag` of the plane counts as on the plane and is projected onto it.
    - Each cut edge gets exactly one new vertex, interpolated from its lower vertex id and then projected onto the plane.
    - A clipped quadrilateral is split along its shorter diagonal.
    - Faces lying in the plane are dropped, and unused vertices are removed.
    - The returned cut edges are the result's boundary edges with both ends on the plane, given as `[tail, head]` of their triangle side and sorted.
    - A zero or non-finite normal returns the mesh unchanged.
7. **mirror_weld**: `WeldReport { seam_verts, open_edges, seam_open_edges, seam_poles, nonmanifold_edges }` (the struct was not defined in DESIGN). Vertices within `tol` of the plane are snapped onto it and shared by both halves. Mirrored faces have their vertex order reversed and keep their face_comp, and mirrored vertices keep their vflag. Faces lying entirely on the seam are not duplicated. `open_edges` counts every boundary edge of the result. `seam_poles` counts the seam vertices that are irregular under the quad_stats rules.
8. Extra public helpers: `aq_eval::{fan_triangulate, poly_from_tris, py_round}` and the constants `loops::{CIRC_COS, HELIX_DRIFT_H}`.
9. The aq_eval tests build their own synthetic meshes (cube sphere, torus grid, open cylinder, helical strip) in `tests/common`, so they do not depend on aq_testkit's progress. **The unused dev-dependency `aq_testkit` was removed from `crates/aq_eval/Cargo.toml`:** while WP-01b was in progress, its half-written crate broke `cargo test -p aq_eval`. Cargo updated the aq_eval entry of `Cargo.lock` to match. The unused `robust` dependency stays declared.

### WP-02 (aq_linalg), 2026-10-29

1. **Signatures that cannot return `Result` keep the DESIGN 6.3 form and get a fallible twin** (3.4 says public functions return `Result`):
    - `cotan_laplacian` and `hermitian_to_real` return an empty 0 x 0 `Csc` on an error; `try_cotan_laplacian` and `try_hermitian_to_real` return the error.
    - `Chol::solve` / `solve_multi` fill the right-hand side with NaN on an error (wrong length, failed workspace allocation, factor invalidated by a failed `refactor`); `try_solve` / `try_solve_multi` return it.
    - `pcg` returns 0 and fills x with NaN on a length mismatch. `pcg_ctl(a, b, x, pre, tol, max_it, Option<&Ctl>) -> Result<PcgInfo { iters, rel_res, converged }>` adds the residual, the convergence flag and `ctl.check()` every iteration. Convergence test: `||b - A x|| <= tol ||b||`. A breakdown stops with `converged = false`.
    - Every error carries `Stage::Engine`; callers restamp with `AqError::at(stage)`.
2. **Storage conventions (not fixed by DESIGN):**
    - `Triplets::push(i, j, v)` adds v to A[i][j] **and** A[j][i]: an off-diagonal pair is pushed once, in either orientation. Duplicates are summed in insertion order.
    - `Csc` is the lower triangle with sorted rows, the diagonal always stored first in its column (an explicit 0 if nothing was pushed), and explicit zeros never dropped, so reassembling with other values keeps the pattern and the `Symbolic` stays valid.
    - `hermitian_to_real` takes a `CTriplets` (n, entries `[re, im]`; `push(i, j, z)` adds z to H[i][j] and conj(z) to H[j][i]; the imaginary part of a diagonal entry is ignored). Unknowns are **interleaved**: `x_i = Re z_i` at 2i, `y_i = Im z_i` at 2i + 1 (`complex_to_real`, `real_to_complex`). Block (i, j) is `[[Re h, -Im h], [Im h, Re h]]`.
    - `cotan_laplacian` is positive semi-definite: `L[i][j] = -w_ij`, `L[i][i] = sum_j w_ij`. `w = (cot a + cot b)/2` (one cotangent on the boundary), times `edge_scale[he]` read on the canonical halfedge (length 3F), **then** clamped with `aq_core::tol::clamp_weight` to [1e-6, 1e6] times the mean |w|. The clamp makes every weight positive (obtuse triangles included). The diagonal is recomputed from the stored off-diagonals, so `L 1 = 0` to one rounding. `lumped_mass` is barycentric (A_f / 3 per corner).
3. **faer runs sequentially (`Par::Seq`).** faer 0.24 parallelizes only inside the dense supernode kernels, and its result then depends on the thread count: on a 41k-vertex sphere Laplacian about half of the solution entries differed in their last bits between 1 and 8 threads, which 3.4 forbids. Sequential was also as fast or faster on surface meshes (small supernodes). The test `chol_deterministic_across_threads` pins bit-identical solutions for 1, 2, 3 and 8 threads on both the simplicial and the supernodal path. Callers get parallelism by solving independent systems concurrently.
4. **Ordering: `Ordering::Auto` (the default of `Chol::analyze`) = AMD, plus, from `ND_MIN_N` = 20000 unknowns, a nested dissection; the one with the smaller operation count (`sum_j c_j^2` over the exact column counts of L) is kept, AMD on a tie.** The two are computed concurrently (`rayon::join`, deterministic). The nested dissection is George's level-set bisection (pseudo-peripheral BFS root, smallest level leaving at least 30% on each side, separator thinned), leaves of at most 512 vertices ordered by faer's AMD, no recursion. Measured operation counts at about 200k vertices: noisy icosphere 2.4e9 (ND) vs 5.8e9 (AMD); jittered plane 1.95e9 vs 2.03e9; regular torus 3.2e9 (AMD kept) vs 4.2e9. `Chol::analyze_with(a, Ordering::{Amd, NestedDissection, Auto})` forces one; `Symbolic::{ordering, flops, factor_len, perm, is_supernodal, matches}` report.
    - **Why this matters for the 6.3 timing test:** with AMD alone faer's analysis is cheap (about 0.1 s at 200k) and the numeric factorization is 75 to 80% of analyze + factor, so "refactor < 60% of the full time" failed (measured 77%). The ordering search is a genuine analysis cost that every refactor saves, as with CHOLMOD's AMD/METIS choice. Measured best of 3 on this machine under heavy load from parallel builds: torus 204800 vertices analyze + factor 0.54 s, in-place refactor 48%; noisy icosphere 163842: 0.73 s, 49%; jittered plane 203401: 0.82 s, 45%. All are below 1.5 s.
5. **API additions:** `Chol::new` (analyze + factor), `Chol::refactor(&mut self, a)` (numeric refactor in place, no allocation; on failure the factor is invalid until the next success), `Chol::{n, symbolic}`; `Csc::{from_parts, from_triplets, from_diag, identity, validate, same_pattern, get, diag, mean_diag, add_diag, add_diag_vec, scale, lin_comb, mul_vec, try_mul_vec, quad_form, to_dense, col_ptr, row_idx, values, values_mut, n, nnz}`; `Triplets::{new, with_capacity, push, clear, to_csc, n, len}`; `Jacobi::{new, apply}`; `cotan_weights` (the clamped weights per canonical halfedge); module `dense` with `lu_solve` (partial pivoting) and `sym_eigen` (row-major, ascending), so no other crate needs faer for small blocks.
6. **Elim details:**
    - `pin(var, value_zero)` returns a `RowOutcome` (callers may ignore it). `value_zero = true`: the variable is 0 and disappears from every expression; pinning an already eliminated variable to zero is the row `x_var = 0`. `value_zero = false`: the variable keeps a caller-supplied value and stays as a term in expressions (`eval_with` takes the values); a row that reduces to value-pinned terms only is `Inconsistent`, and pinning an eliminated variable to a value is `Inconsistent`.
    - A row naming a variable out of range returns `Inconsistent` (no panic). An i64 overflow while substituting returns `NoUnitPivot` with the state unchanged (the caller makes the row a penalty).
    - `expr(free var) = [(var, 1)]`, `expr(zero-pinned) = []`; expressions are sorted by variable id. `free_index` numbers the free variables in increasing id order; the table is rebuilt lazily after a change. Extras: `n_vars, is_free, is_pinned, is_value_pinned, free_vars, max_abs_coeff, substitute, eval, eval_with`.
7. **Cholesky of a singular PSD matrix may succeed** with a tiny pivot (a graph Laplacian without mass factors with a last pivot of about 1e-8); `Numerical` is raised for a non-positive pivot only. Callers that can be singular must pin or regularize first (as 6.6 and 6.9 already do). faer 0.24 reports the failing pivot 1-based on its simplicial path and 0-based on the supernodal one; `Chol::factor` corrects this and names the original column.
8. **Tests:** the crate carries its own mesh generators (`tests/common`, adapted from aq_core's), and **the unused dev-dependency `aq_testkit` was removed** from `crates/aq_linalg/Cargo.toml` so the tests do not depend on WP-01b's progress (Cargo updated the aq_linalg entry of `Cargo.lock`). Sizes DESIGN leaves open: PCG on a 64 x 64 Dirichlet Poisson grid (plain and with varying coefficients; 193 and 224 iterations); random Elim rows of 2 to 4 terms with +-1 coefficients (10000 rows over 20000 variables with mesh-like locality, plus 2000 uniformly random rows over 3000 variables, plus an overdetermined case; max |coeff| 20); timing on three 160k to 205k vertex meshes, best of 3 runs, in a rayon pool of 8 threads, skipped in debug builds.

### WP-02 review follow-up (aq_linalg), 2026-10-29

1. **Nested dissection on fragmented patterns was quadratic (review major, fixed).** Each pass of the task loop removed only the component of `verts[0]` and copied the whole remainder into a new task, so the cost was O(n x components). Measured before the fix: 200k isolated unknowns took 52 s in the default `Chol::analyze`, and the ND result was then discarded (AMD kept). Now a disconnected task is split into all of its components in one O(task) pass. Components of at most the leaf size (512) are batched, in order, into leaf tasks over consecutive positions (AMD on the union). Measured after the fix, best of 3, analyze time AMD alone vs Auto:
    - 200k isolated unknowns: 0.037 s vs 0.047 s.
    - 100k 2x2 blocks: 0.055 s vs 0.057 s.
    - 300 x 300 grid with 30% of its grid rows pinned by identity rows: 0.062 s vs 0.060 s.
    - 250 x 250 grid plus 150k isolated unknowns: 0.159 s vs 0.177 s (ND kept).
    - Regression tests: `auto_ordering_overhead_on_fragmented_patterns` (tests/timing.rs, release only) asserts Auto < 3 x AMD + 50 ms on these four patterns. `nested_dissection_on_fragmented_patterns` (tests/chol.rs, debug too) checks the permutation and the solve with forced ND and Auto, with components above the leaf size interleaved with small ones and a randomly relabeled index.
2. **`Chol::analyze_ctl(a, ord, Option<&Ctl>)`** (new). It calls `ctl.check()` once per ND task, every 4096 columns of the operation counts, and before and after faer's AMD and symbolic factorization. `analyze` and `analyze_with` keep the DESIGN 6.3 form (no ctl). **Known limit:** faer's AMD, its symbolic analysis and the numeric factorization (`factor`, `refactor`) cannot be interrupted. At 200k unknowns that is about 0.1 s for the analysis and 0.3 to 0.7 s for a factorization, during which cancel and timeout are not seen. DESIGN 6.3 gives no ctl parameter, so this is a gap in the design. **Request to the integrator:** stages that factor large systems in a loop (6.6, 6.9) should call `analyze_ctl` and `ctl.check()` between factorizations, and the 3.4 "every 10 ms" rule needs an explicit exception for one sparse factorization.
3. **DESIGN threshold issue: "numeric refactor < 60% of analyze + factor" is not meaningful when AMD is kept.** faer's AMD analysis is cheap (about 0.1 s at 200k), so the numeric factorization is 75 to 80% of analyze + factor on the torus. The test passes there (46 to 57% measured) only because `Ordering::Auto` also computes a nested dissection and two operation counts, and this work is then discarded. Against the kept ordering alone the torus ratio is 60 to 77% (60% in the last run, 77% earlier). The noisy icosphere and the jittered plane keep ND, and their ratio is 38 to 44% against the kept ordering alone, so there the saving is real. The test keeps the DESIGN assertion and now also prints the "kept-only" ratio. **The torus margin is small:** if it fails on a loaded machine, re-run it before treating it as a regression. **Request to the integrator:** restate the criterion, for example "refactor <= factor + 10%" or "reusing the analysis saves its measured cost".
4. **Supernodal pivot correction is now tested.** The 2D 150 x 150 grids of `non_spd_reports_column` stay on faer's simplicial path (the old comment was wrong and is fixed). A 3D 7-point grid with 20^3 unknowns asserts `is_supernodal()` and checks that the right column is named for bad columns 0, 4321 and 7999.
5. **lap.rs uses the aq_core halfedge helpers** (`Topology::tail`, `head`, `prev`, `is_canonical`, `twin_of`) instead of re-deriving the C2 rules. A twin index out of range (>= 3F) now gives `InvalidInput` instead of a panic (tested).
6. **Fallible allocation (3.4):**
    - `Elim::try_new(n) -> Result<Elim, AqError>` returns `Budget`. `Elim::new` keeps the DESIGN signature and aborts on allocation failure, as before.
    - `try_lumped_mass` returns `Budget`. `lumped_mass` returns an empty vector on failure.

### WP-14 (aq_post), 2026-10-29

1. **`relax` takes `px: &PostProxy`, not `&Proxy`.** `Proxy` is an aq_prep type and aq_post depends on aq_core only (3.2). `aq_post::PostProxy { mesh, topo, frames, feats, bvh }` borrows the same proxy parts plus the BVH the projector needs; the engine builds it with `PostProxy::new(&px.mesh, &px.topo, &px.frames, &px.feats, &bvh)`. `chain_of_vert[v]` is a proxy chain id (index into `px.feats.chains`) or NONE, one entry per quad vertex.
2. **Source faces.** `QuadMesh` carries no source face per vertex, so the projection hints are computed once at start-up: the BVH closest face for free and fixed vertices, the face of the closest chain segment's halfedge for chain vertices. Each accepted move then updates the hint. The start-up queries run in parallel; the sweeps are Gauss-Seidel in vertex id order on one thread, so the result is bit-identical for any thread count (tested with 1 and 4 threads).
3. **Interior move.** Target = area-weighted mean of the incident face centroids (any polygon, Newell area), its offset projected to the tangent plane of the proxy face under the vertex, then `Projector::project(target, hint, n_hint)`. A `None` projection drops the move (counted).
4. **Chain move.** The same target, then the closest point on the chain polyline, searched only among the segments within an arc length of 3 times the move distance from the vertex's current point (wrapping on closed chains), so a vertex cannot jump to a distant part of a folded chain. The result is a point of a polyline segment, so it stays on the polyline to rounding (measured 2e-16). At start-up a chain vertex within `CHAIN_SNAP_MAX` = 1e-3 of its polyline is snapped onto it; a farther one is kept fixed and counted in `chain_off`.
5. **Roles.** vflag bit 24 (corner) is fixed throughout; bit 25 (cone) is frozen for the first `freeze_nodes_iters` sweeps, then moves as an interior or chain vertex. A quad-mesh boundary vertex without a chain, and a vertex used by no face, are fixed (no polyline to slide on).
6. **60 degree test, precise rule.** For each face incident to the moved vertex, the reference surface normal is the mean proxy normal at the hints of its interior corners (of all its corners when none is interior), so a quad next to a hard crease is judged against its own side. Only the corners whose normal depends on the moved vertex are tested. A move is accepted when the smallest corner cosine after the move is >= cos 60 degrees, **or when it is larger than before the move**: without the second clause a corner that is already bad (a fold left by S10, or a jittered input) would freeze its vertices forever. The jittered sphere test starts with folded corners (min cosine -0.95) and ends at 0.999.
7. **Cleanup API.** `cleanup(q)` keeps the DESIGN signature with h = 1 (quad units, C14). `cleanup_with(q, &CleanupParams { h, small_area: 0.3, max_passes: 8 })` takes another h. `CleanupReport { doublets, diag_collapses, faces_before, faces_after, verts_before, verts_after, vert_map, skipped }`; `vert_map` maps old to new vertex ids (NONE for a removed vertex), so the engine can remap per-vertex arrays such as `chain_of_vert`. An invalid mesh (`QuadMesh::validate` fails) is left untouched with `skipped = true` (the function is infallible as specified).
8. **Cleanup rules.** Vertices with chain bits, the corner bit or the boundary bit are never removed. A doublet is an interior vertex with exactly two quad faces `[v, b, c, a]` and `[v, a, d, b]` (c != d); they become `[b, c, a, d]`. A 3-3 diagonal pair is two opposite vertices of a quad of area < 0.3 h^2 that are interior, unprotected and have 3 faces each; it is collapsed into their midpoint when the link condition holds (the two share only that quad and only the two other corners as neighbours), the two other corners keep at least 3 faces (1 on the boundary), and no affected face or corner normal flips. The merged vertex has valence 4 and loses the cone bit. Small quads are visited in increasing area (ties by face id), doublets are removed before and after each collapse pass. Cones may be merged (that is the point of the collapse).
9. **`RelaxReport`** was not defined in DESIGN: `{ iters, interior_verts, chain_verts, fixed_verts, cone_verts, moved, rejected_normal, projection_failed, chain_snapped, max_snap, chain_off, max_step, max_disp, mean_disp }`.
10. **Tests** (`crates/aq_post/tests/post.rs`): jittered grid edge CV 0.236 to 0.003; perfect grid max move 0; chain vertices on a curved hard chain across a creased warped surface and on two boundary chains stay within 2e-16 of their polylines; jittered cube-sphere on an icosphere proxy ends with no inversion (min corner cosine 0.999); kinked arc between two patches 41.1 to 4.0 degrees; planted doublet removed; planted 3-3 pair collapsed back to the regular grid; freeze rules; errors and cancel; thread-count determinism. Added: 5.4k quads on an 82k-face proxy, relax + cleanup in 0.26 s (budget 1 s, 7.4).

### WP-09 (aq_cut + aq_loops), 2026-10-29

1. **`cut_and_comb`, `homology_generators`, `find_loops` and `trace_streamline` take `px: &ProxyRef`, not `&Proxy`.** `Proxy` is an aq_prep type and both crates depend on aq_core only (3.2). `aq_cut::ProxyRef` and `aq_loops::ProxyRef` are the same borrowed view `{ mesh, topo, frames, feats }`; the engine builds them with `ProxyRef::new(&px.mesh, &px.topo, &px.frames, &px.feats)` (same pattern as WP-14's `PostProxy`). See the core change request below.

2. **aq_cut details DESIGN leaves open:**
    - Dijkstra cost = dual edge length through the edge midpoint (`|c_f - m_e| + |m_e - c_g|`). Heap ties go to the lowest face id. Roots: the largest face of each component; exact area ties are broken by one `SplitMix64(seed)` drawn over the components in order. Combing follows the Dijkstra tree in settle order (parents first), which gives the same offsets as a BFS of that tree.
    - Nodes are exactly DESIGN's set (cut degree != 2, cones on the cut, cut vertices on the boundary) plus, for a node-free cut cycle, its lowest vertex. Feature corners are kept by the pruning but are not nodes (aq_testkit's `analytic_cut` also makes them nodes).
    - **"Every cone lies on the cut" holds for interior cones.** Boundary cones (the 4 corners of a planar square, index4 +1) are on the boundary, which is already the boundary of the disk; pruning never stops at them for their own sake, so a disk without interior cones gets an empty cut. The tests check interior cones on the cut (and as nodes) and boundary cones on the cut or the boundary.
    - `homology_generators`: union-find spanning forest of the cut graph with all boundary vertices of a component merged into one super-vertex; each cut edge closing a cycle gives one dual cycle (cross it, then the non-cut dual forest back). Count `2g` (closed) or `2g + b - 1` (b > 0 boundary loops). Each cycle is a halfedge list in the `LoopCand::hes` format.
    - Extra public items: `cut_mesh_euler(px, is_cut) -> Vec<i64>` (per component, wedge-duplicated vertices; an empty Vec when `is_cut.len() != 3 * n_faces` or the topology does not match the mesh, never a panic).
    - Errors carry `Stage::Cut`: `InvalidInput` for size mismatches, `Invariant` for a closed genus-0 component without cones, a non-disk cut, or r varying along an arc.

3. **aq_loops seeds: the seed rng picks the first farthest-point seed, and the farthest-point order is kept (not shuffled).** DESIGN shuffles the seed order. With "rings first, then shortest first", equal loops (all rings of a cylinder) are then accepted in random order, which is a random sequential packing at the 6h exclusion distance: on an 18h cylinder it accepted 2 rings, below DESIGN's own test "at least 1 ring per 6h of length" (3). The farthest-point order spreads equal loops apart (3 rings). So: loops are sorted rings first, then by length; loops within 5% (`LENGTH_GROUP`) of the shortest loop of their group are ordered by seed rank, then branch. The seed still drives the result (C15) through the first seed.

4. **aq_loops clustering "same combed family"** is decided geometrically: S5 runs before the cut, so no combing exists yet. For each sample of the candidate (about every 0.5h, `SAMPLE_STEP`), the nearest sample of every accepted loop within `cluster` h (3D distance) is found; the sample counts as near when one of those nearest samples has a tangent within 45 degrees. Comparing at the nearest point matters: comparing any sample pair within 6h made the longitudes of a torus "parallel" to far points of meridians (3D tangents at different places on a curved surface) and rejected every longitude.

5. **aq_loops turning test: "60 degrees beyond the holonomy" is replaced by a Gauss-Bonnet test (`turning_check`).** (This item was rewritten after review; the first version was wrong.)
    - **Why the DESIGN wording cannot be implemented literally.** With `T = sum delta[he]` (the signed geodesic turning of the field line, C8) and `H = sum kappa[he]` over the closed dual cycle, theta telescopes, so `T + H = -(pi/2) sum p`, a multiple of 2pi for any cycle that returns to its branch. The holonomy H is therefore only known mod 2pi and says nothing about T. The first implementation tested `|T - wrap_pi(-H)| <= 60 degrees`; that quantity is always 0 or at least 2pi, so the rule was exactly "accept iff `|T| <= pi`" and the 60 degree bound never decided anything. It rejected every contractible loop over a flat or near-flat region (turning near 2pi), that is the eye-socket and mouth loops that 6.7's Purpose names, and every torus parallel with `|sin(latitude)| > 1/2`.
    - **Rule now.** The net crossings of the cycle per edge define a winding number w on the vertices (`w(head) = w(tail) + 1` across each crossed halfedge, C3). The vertices are flooded into cells through the edges with no net crossing. Then:
        - *Separating* (2 cells, w differing by 1): Gauss-Bonnet on the left side D predicts `T = 2pi chi(D) - K(D)`, K = sum of `Frames::angle_defect` (`pi - omega` on the boundary), chi = V - E + F of the vertices of D and the edges and faces they span. Rejected when `|T - prediction| > 60 degrees` (`MAX_TURNING_EXCESS`).
        - *Non-separating* (1 cell, no edge crossed twice in the same direction: torus meridians and parallels, (p, q) torus loops): no Gauss-Bonnet prediction exists, accepted at any turning (a torus top circle turns by 2pi and is a valid ring).
        - *Overlapping* (anything else: an edge crossed twice net, more than 2 cells, w range above 1, nothing crossed net): rejected. This is the "winding 2 or more" case.
    - **What the 60 degree bound means now.** Because C9 makes `T = sum_v w(v) ((pi/2) index4(v) - K(v))` exact, the excess of a separating cycle is `(pi/2) |index4(D) - 4 chi(D)|`, a Poincare-Hopf residual of D: 0 for a closed field line around D, a multiple of 90 degrees otherwise. So the 60 degree bound separates 0 from 90 degrees and more; it is not a continuous geometric tolerance. It rejects cycles that do not bound what a closed field line must bound (a tight cycle around a regular vertex: excess 2pi; around a single +1 cone: 3pi/2), which is the "spiral around cones" case. Measured on the accepted test loops: excess < 1e-6.
    - **Cost.** The flood grows all cells together and stops when one is left, so a separating loop costs about twice its smaller side, a non-separating one a sweep of its component. The test therefore runs in the sequential clustering pass, only for loops that pass the cluster test (a rejected loop is not inserted and does not block later ones). 100.8k-face torus: 0.15 s before, 0.20 s now (26 full sweeps; budget 0.5 s).
    - **For the integrator.** 6.7's Purpose (eye and mouth loops) is now met, but more loops are accepted than with the first version: flat-cap loops of a closed cylinder, loops near cone clusters on a sphere (turning about 180 to 200 degrees, matching the spherical area they enclose), all torus parallels. DESIGN's test "accepted loops have turning < 60 degrees" is read as "turning within 60 degrees of its Gauss-Bonnet prediction"; a literal `|T| < 60 degrees` would reject every eye loop and every closed field line near a cone pair on a sphere.

6. **aq_loops tracing and closure details:**
    - All lengths in `LoopParams` are in local h (`h_face`); `LoopCand::length` and the ring test use quad units. `trace_streamline` measures `max_len` in mesh units (h = 1). It keeps DESIGN's non-`Result` signature: an invalid start returns an empty `Streamline` with `StopReason::Invalid`.
    - `Streamline` (not defined in DESIGN): `{ start, faces, branches, hes, points, length, stop, stop_he }`, segment i in `faces[i]` from `points[i]` to `points[i+1]`, `hes[i]` crossed from `faces[i]` to `faces[i+1]`.
    - "Hard chain" = kinds Hard and GuideHard (Guide is soft; Boundary and a boundary Symmetry chain stop as boundaries). A cone face is never entered.
    - Eligible seeds: interior, non-cone vertices with mean incident conf >= `min_conf` and at least one non-cone incident face; the trace starts at the centroid of the lowest-id such face. The farthest-point distance is geodesic on edges in h (`l / mean(h_vert)`).
    - Closure is tested only after the trace has left the seed face's 1-ring; the branch is compared after carrying it along the closing path (the shortest dual path inside the 1-ring, BFS), and the closest segment of that visit to the 1-ring closes the loop.
    - Vertex hits: an exit within 1e-9 h of a vertex is recomputed with the ray origin moved 4e-9 h to the left (CCW side) of the ray.
    - Extra public items: `find_loops_report` (accepted `LoopInfo` with closure error, turning, expected turning, excess, `cycle: CycleKind`, mean |k1|, seed and samples, plus a `LoopReport` of counters including `rejected_turning` and `rejected_overlap`), `loop_turning(px, f, hes) -> (T, H)`, `turning_check(px, f, hes, ctl) -> Result<TurningCheck, AqError>` with `TurningCheck { kind, turning, expected, excess, side_left, side_chi, side_k }` and `CycleKind { Separating, NonSeparating, Overlapping }`, `StopReason`, `LoopParams::default()` (DESIGN 13 values), constants `MAX_TURNING_EXCESS`, `LENGTH_GROUP`, `SAMPLE_STEP`.

### WP-12 (aq_quantize), 2026-10-29

1. **Weights and lower bounds come from the DESIGN 6.11 table, not from `TArc.weight` / `TArc.lb`.** `quantize` recomputes them per arc at every scale sigma (`arc_weight`, `table_lb`, `arc_target` are public), because `allow_collapse` and the rule "lb 1 when sigma l >= 0.5" are S9 decisions and testkit fills `TArc.lb` with `allow_collapse = false`. The cost denominator of a wrap arc stays `max(sigma l, 0.5)`; only its target is 0. `TArc.lb` and `TArc.weight` are informational for S9.
2. **API additions** (DESIGN signatures unchanged): `QuantParams::default()` (DESIGN 13 values, `allow_collapse = true`); `QuantResult.lb` (final lower bound per arc: table bound at the returned sigma raised by the cuts, so a test or the engine can see where a cut landed); `build_comb_with(t, n, ring_min)` (`build_comb` cannot take `ring_min`, it uses the default 8); `comb_violations(t, n, ring_min)` (every violation with the zero arcs that caused it); `objective(t, sigma, n)`; `MAX_SOLVES = 24`; `Violation` derives `Clone, Debug, PartialEq, Eq, PartialOrd, Ord, Hash`.
3. **`Violation::Unbalanced(u32)` added**: `n` does not fit the T-mesh (patch id whose opposite sides differ, or `NONE` for a wrong-length `n` or a QComb above 2^31 union-find elements). None of the DESIGN variants describes that input error. Violation payloads: `NonManifold` = QComb vertex ids, `BadValence` / `CornerMerge` = QComb vertex id, `Pinch` = patch id, `ShortRing` = index into `TMesh.rings`, `Euler` = the computed Euler characteristic.
4. **QComb of a zero patch keeps its ids**: `patch_dims` holds the real `[W, 0]` (or `[0, H]`) and `patch_ids` the `(W+1)(H+1)` glued ids, so aq_patch can see the gluing (`QComb::validate` accepts both forms). A zero arc has one id; ids are numbered by first element in the order nodes, arc samples, patch grids, so `node_id` comes first and the numbering is deterministic.
5. **Validity rules where DESIGN is open:**
    - (i) non-manifold also covers a vertex in no quad and a vertex whose quads form more than one fan; a doublet is two quads sharing two or more edges.
    - (ii) the valence test applies to every interior QComb vertex (boundary vertices are not tested); the index test to every vertex holding 2 or more T-mesh nodes.
    - (iii) corners are `FeatureCorner` and `BoundaryCorner` nodes; corners of the same chain may merge (their index sum is still tested by (ii)).
    - (iv) a glued zero patch pinches when its two glued sides carry arcs of two different chain ids (boundary loops are separate chains).
    - Causes: every union made by a collapse is recorded (a zero arc joining its end nodes, a zero patch gluing side 2 to side 0 or side 3 to side 1); a violation's cause set is the zero arcs recorded in the classes involved (all of them for `Euler`; the collapsed sides' zero arcs for `Pinch`; the ring's zero arcs for `ShortRing`).
    - A `ShortRing` without a zero arc gets one more segment (lb = n + 1) on its arc with the largest `sigma l / (n + 1)`, since raising lb to 1 cannot help it.
    - When a validity round adds no new cut, the "lb = 1 on every arc" solve runs at once instead of repeating identical rounds. Cuts and that fallback persist across secant steps.
6. **Solver details.**
    - Step 1 is a primal-dual successive shortest path: one multi-source Dijkstra on reduced costs (early stop at the first target, potentials updated only on the settled nodes), then every remaining admissible (zero reduced cost) path is augmented by DFS before the next Dijkstra. Every admissible path is a shortest path, so this is the same SSP with far fewer searches (24 ms to 2 ms on the 7k-arc test grid). The ground's two copies are one node (its balance is free). Stage A routes excess to deficits or the ground, stage B feeds the remaining deficits from the ground. Capacity scaling: start at the largest power of two not above the largest |excess| when the total excess is above 2000, and saturate negative delta-residual edges at the start of each phase (convex-cost scaling).
    - Steps 2 and 3 are as specified; the "pair imbalanced nodes greedily" part of step 2 and the step 3 fallback are one routine: cheapest double cover path (Dijkstra, negative marginal costs clamped to 0) from the imbalanced node to a compensating node, to itself with the other sign when |imbalance| >= 2, or to the ground. A path whose net change would break a lower bound is retried with that arc's decrease blocked. Cap 4 |arcs| moves, then `Infeasible`.
    - **Step 4 added, polish:** improving closed walks of the double cover (negative cycles of the true marginal costs, FIFO Bellman-Ford from a virtual source, predecessor-graph cycle check after each pass) are applied while one exists and its real gain is negative, at most 64 per solve and within a work budget of 48 passes over the edges. A closed walk keeps every constraint balanced, so it is always a feasible move.
7. **Tests, interpretations:**
    - "200 random bi-directed instances" is run at sigma = 1 and also at sigma = 0.73, 1.37, 1.5 and 2.3, each with and without collapse. At sigma = 1 the testkit instances are trivial: their noise is below 0.45, so `round(len)` (the planted feasible solution) is every arc's own minimizer, and no instance reaches the parity or repair steps. At the other scales about 11% of the instances have a half-integral relaxation (all odd cycles, so all go through the integer repair). Measured: 197 to 200 of 200 optimal per scale, worst ratio 1.12. The brute force is a branch and bound bounded by the solver's own objective, with constraint pruning.

A uniform grid is not used: all its columns share one width, so its count is a step function of sigma.

### WP-07 (aq_curv), 2026-10-29

1. **`curvature` and `sizing` take `px: &ProxyRef`, not `&Proxy`** (`Proxy` is an aq_prep type; aq_curv depends on aq_core and aq_linalg only, 3.2). `aq_curv::ProxyRef { mesh, topo, frames, feats }` is field for field WP-09's view; the engine builds it with `ProxyRef::new(&px.mesh, &px.topo, &px.frames, &px.feats)`. The density is not in the view: `sizing_with(px, c, p, density: Option<&[f64]>, ctl) -> (SizeField, SizingReport)` takes the per-vertex rho (`Proxy.density`, already raised to density_strength by `transfer_density`); `sizing` (DESIGN signature) is `sizing_with(.., None, ..)`. In M1 the engine passes adaptive 0 and no density.

2. **Normal leak return in steps 4 and 6 (deviation, needed for the sphere test).** Diffusing the ambient 3x3 tensor over a curved surface rotates part of its tangent content into the normal direction: on a sphere of radius R the diffused tensor is `(1/R)(a I - b n n^T)` (the l = 2 harmonics decay by `1/(1 + 6t/R^2)`), so the projection `P T P` alone gives k = 0.8/R for R = 2, t = 1, while the trace (the mean curvature) is preserved. Measured on icosphere(3), R = 2: mean k1 0.400 as written, 0.502 with the return (exact 0.5). The projection therefore adds `(n^T T n)/2` to both tangent eigenvalues (the trace is given back isotropically; kappa_hat does the same with the vertex normal). It is exact on spheres, a no-op on cylinders (`T = (1/R) a a^T` has no normal part) and second order elsewhere. Pinned by the unit test `leak_return_on_sphere`.

3. **Normalization order (precise rule).** The tube cap and the gradation are absolute (quad units), and the gradation inequality `log h(y) <= log h(x) + grad |xy| / h(x)` is not scale invariant, so "normalize, cap again, renormalize" cannot leave both the caps and the gradation intact. The final field is `h = Grade(min(s g, cap))`, with s found by a safeguarded root search on `ln count(s) = ln N` (bracket by doubling from `s0 = sqrt(sum A/g^2 / N)`, then Illinois regula falsi; count(s) is continuous and non-increasing), followed by one exact rescale by `sqrt(count/N)` (a factor within about 1e-14 of 1). Without active caps or gradation this is exactly DESIGN's `s = s0` (2 evaluations, h uniform bit for bit). Measured: gradation excess at most 2.5e-16, count error below 1e-9, 5 to 12 evaluations when caps are active.

4. **Infeasible caps: the count wins.** When the caps alone need N quads or more (for example a whole component that is a thin tube at N = A), no s reaches N; this is detected directly from the limit `count(s = infinity)`. The capped, graded shape at `s* = max(s0, max cap/g)` is then scaled up uniformly (and regraded) until it gives N, and `SizingReport { cap_infeasible: true, cap_relax }` reports the factor (2.6 for a tube R = 0.5 alone, so it gets about 3 quads around instead of 8). Reason: the S3 invariant (7.3) requires `sum A/h^2 = N_c`. **Note for the integrator:** the engine may want to warn, or to raise N_c for such components (the DESIGN floors are only 24 and 8 quads).

5. **Details DESIGN leaves open:** `h_face` is the mean of its 3 vertex values (exactly the common value when they agree). The tube cap of a vertex is the smallest bound over its incident tube faces (conf > 0.5 and anisotropy > 0.6), so every tube face also has `h_face <= 2pi/(ring_min |k1_f|)`; ring_min = 0 disables the cap. `h_f` in the confidence gate is the mean of the 3 `h_vert` passed to `curvature`. kappa_ref is the area-weighted median over barycentric vertex areas, floored at 1e-3 (`KAPPA_REF_MIN`) so that a flat component does not divide by zero. Boundary edges have no dihedral angle. An isolated vertex gets a unit mass (its tensor is 0). Inputs are validated (`InvalidInput`): sizes, h finite and positive, scale > 0, conf_lo < conf_hi, n_target finite and positive, adaptive in [0, 1], grad > 0, density finite and positive. Errors carry `Stage::Curv`.

6. **Not implemented in M1:** the thickness cap (M2, WP-20). `thickness = true` is accepted and reported in `SizingReport.thickness_skipped`. The adaptive term and the density factor of the base g are implemented (one line each); the M2 sphere-with-bump gate is WP-20's. A sanity test (Gaussian bump on a plane, adaptive = 1) gives a bump/flat quad density ratio of 4.3.

7. **API additions:** `curvature_and_sizing(px, density, &CurvParams, &SizingParams, ctl) -> (CurvField, SizeField, S3Report)` (the two-pass driver of 6.5: pass 2, with t from pass 1's h, runs only when adaptive > 0 or a density is given; the M2 adaptive proxy re-remesh between the passes stays with the engine and aq_prep), `CurvParams::default()` (1.0, 0.02, 0.25), `SizingParams::new(n_target)` (adaptive 0, ring_min 8, grad 0.25, no thickness), `SizingReport`, `S3Report`, `curvature_detail` (diffused vertex tensors and per-face anisotropy), `dihedral`, `smoothstep`, `anisotropy`, `confidence`, and the constants `TUBE_CONF`, `TUBE_ANISO`, `G_MIN`, `G_MAX`, `KAPPA_REF_MIN`.

8. **Tests and measurements** (`crates/aq_curv/tests/curvature.rs` and `sizing.rs`, release):
    - Sphere R = 2 (icosphere(3) and uv_sphere(20, 38)): max |k - 0.5| / 0.5 = 0.52%, conf 0.
    - Cylinders R = 2, 5, 10 (edges h/3, jitter 0.2, measured more than R from the ends): |k1| error 0.22%, 0.13%, 0.15%; |k2| R at most 0.0025; direction within 3 degrees on 100% of faces; min conf 0.995, 0.874, 0.277.
    - **Noisy cylinder: DESIGN does not fix R; the test runs at R = 2 (98.9% of faces within 5 degrees).** For information: R = 5 gives 57%, R = 10 gives 9%. The amplitude 0.02R grows with R while the signal 1/R shrinks, and a wavelength of 0.2h is below the proxy sampling (h/3), so at R = 5 the noise is aliased white noise of amplitude 0.1h. One implicit diffusion step is only a first-order low-pass: the curvature noise of a displacement passes as `k^2 / (1 + t k^2)`, which tends to 1/t. Two half-steps with the same factorization were measured at 73% for R = 5 and not adopted. Also measured: the conf gate does not filter that noise (the noisy R = 10 cylinder has mean conf 0.29, the same as the clean one), so on very noisy inputs robustness rests on the field's smoothness term; flow_smoothness > 1 is the user lever. **Input for risk 3 (WP-08, WP-16).**
    - Saddle z = (x^2 - y^2)/4: conf > 0.5 within radius 1 of the origin, k1 k2 < 0. The diffused |k1| at the origin is 0.27, not 0.5: ambient diffusion over about 1.4h rotates the tensor across the kernel, and the leak return is zero on a saddle. kappa_hat is therefore underestimated on strongly curved saddles (this only matters for M2 adaptive sizing).
    - Sizing: in the uniform case h is equal bit for bit and `|sum A/h^2 - N| < 1e-9`. Thin cylinder R = 0.5 next to a flat sheet (N = A): min `2piR/h` = 8.11 on the tube, and the sheet takes the rest. Thin tube alone: the count wins (item 4). Flared tube (R 0.4 to 3) at grad 0.1, 0.25 and 1: gradation within 2.5e-16 on every edge, the cap holds as defined, count exact (grad 0.1 is infeasible there: the caps grade the whole flare down). A 4x density halves h. Determinism with 1, 4 and 16 threads (bitwise).
    - Performance: 100k-triangle noisy torus, adaptive = 1 (both passes): 0.54 s best of 3 (budget 1.5 s). Up to 1.4 s was measured while parallel builds loaded the machine.
    - testdata smoke run (scaled to quad units for N = 3000): 11 of 12 run without error. `retopo_a` is skipped because aq_core rejects its bowtie vertex (aq_prep's ingest splits it in the pipeline).
    - **Note for WP-03 (proxy quality):** on sliver triangles the clamped cotan weights over-diffuse. On a tube of 0.05 x 0.33 cells with z jitter, a step decayed over about 2h instead of h (unjittered: exactly the 1D theory, e^-d). The isotropic proxy (min angle >= 25 degrees on 98% of faces) avoids this, but the scale S3 measures at depends on it. The flared-tube test mesh is built without jitter for this reason.

9. **Ctl:** `ctl.check()` runs every 16384 halfedges, before and after the analysis and the factorization (`Chol::analyze_ctl`), after the solves and the per-face pass, once per count evaluation, and every 4096 heap pops of the gradation. ### WP-13 (aq_patch), 2026-10-29

1. **`mesh_patches(lay, q: &QComb, p, ctl)` takes the QComb, not `&QuantResult`.** `QuantResult` lives in aq_quantize and aq_patch depends on aq_core and aq_linalg only (3.2). The engine passes `&quant.comb`. The arc lengths are recovered as `n_a = arc_ids[a].len() - 1` and checked against `patch_dims`, so nothing else of `QuantResult` is needed. The input is checked with `QComb::validate(&lay.tmesh)` (a mismatch is `InvalidInput`).
2. **API additions:** `mesh_patches_with(lay, q, chain_kind: &[FeatureKind], p, ctl)` (FeatureKind per chain id for vflag bits 20..23), `mesh_patches_full` returning `PatchOutput { mesh, report, grids: Vec<PatchGrid>, samples: Vec<ArcSamples> }` (per-patch grid ids, final positions, reference normals and map kind, for the engine's 7.3 check "shared arc samples bitwise equal"), `arc_samples`, `presplit` / `PreSplit`, `sd_barrier_trace` / `SdTrace { iters, energies, restarted }`, `sd_energy`, `count_flips`, `MapKind`, `M2`, `PatchParams::default()` (20, 1e-3). `PatchReport` counts the **final** map kind of every meshed patch (`field_aligned + barrier + floater` = meshed patches; a re-meshed patch counts in `floater` and in `remeshed`) and gains `zero_patches` (glued patches, not meshed) and `split_edges` (pre-split count).
3. **Pre-split rule: every interior edge whose two endpoints are boundary vertices is split** (a superset of DESIGN's rule). It splits the interior edges of every triangle with 3 boundary vertices, including those with 3 vertices on one side, and also any other "dividing edge" between two boundary vertices, which Floater's bijectivity theorem excludes for a weakly convex boundary (an edge with both ends on one straight side collapses the region beyond it). New vertices are midpoints in 3D and in the patch uv; edges are split in increasing (lo, hi) vertex order.
4. **Zero arcs at the end of a side.** DESIGN carves a zero-arc run `[k, k + m eps]` from the next positive arc of the side. When no positive arc follows on that side, the run occupies `[k - m eps, k]`, carved from the end of the previous positive arc. eps is reduced to `0.25 / (zeros on the side + 1)` when a side carries very many zero arcs, so positive arcs keep positive intervals.
5. **Patch chart orientation.** After unfolding the patch through the transitions from `patch_chart_face`, the chart is turned by the quarter rotation that makes side 0's chord run closest to +u. For a layout meeting 6.10 ("side0 runs +u") this is the identity; it protects the targets against a chart face taken from a rotated chart (tested by re-charting part of a patch with r = 1 and r = 3).
6. **Arc samples** use `len_a = arc_s.last()` (equal to `TArc.len` within 1e-9, `Layout::validate`), so the last sample is the end node exactly; samples 0 and n_a are the node vertices bit for bit. A QComb id gets the average of its nodes' W' positions when it holds nodes, otherwise the average of its arc interior samples (ids glued by a zero patch); a single contribution is copied unchanged.
7. **Targets and degenerate faces.** `T_f = diag(W/l0, H/l1) J_f^seam` in the C4 frame of each disk face, with l0, l1 the means of the parametric side lengths (`TArc.len`). A face whose seamless Jacobian is degenerate or folded (det <= 0, possible on `SeamlessParam.folded` faces) gets the isotropic target `sqrt(W H / A_patch) I`. Faces with `2A <= 1e-14 l_max^2` in 3D are left out of the least squares and of the symmetric Dirichlet energy (they are still kept positive by the line search and checked by orient2d).
8. **Least squares** are assembled exactly from the hat gradients (`K_ij = sum A_f g_i . g_j`, not `aq_linalg::cotan_laplacian`, whose weight clamp would change the energy) and factored once with `aq_linalg::Chol`; the barrier's global steps reuse the factor.
9. **sd_barrier details.** `targets[f]` is in the C4 frame of face f of `disk` and must have det > 0 (`InvalidInput` otherwise). Energy `sum A_f (|D|^2 + |D^-1|^2)`, `D = J T^-1`, infinite on a fold. Local step: the rotation closest to D (2D polar, the SVD rotation); global step toward `R_f T_f` with the fixed vertices held; step `min(1, 0.8 t_max)` from the per-face quadratic, halved until Armijo (c = 1e-4) holds, the energy strictly decreases and exact orient2d keeps every triangle positive; it stops when no step is accepted, when the direction is not a descent direction, or when the update is below 1e-13. **A folded input map is replaced by the Floater map** with the fixed vertices as boundary (a barrier cannot start from a fold), reported by `SdTrace::restarted`. The return value is the number of accepted steps.
10. **Floater solve.** The mean value system is not symmetric and aq_linalg has only SPD solvers, so it is solved locally: BiCGSTAB on the row-normalized matrix (unit diagonal) to a relative residual of 1e-14, with Gauss-Seidel sweeps (at most 20000) as the fallback. `floater_mvc` requires every boundary vertex of the disk in `boundary_uv` (`InvalidInput`); extra fixed interior vertices are allowed.
11. **Ladder per patch:** the least squares map is accepted when every triangle is positive (exact orient2d) and every interior grid point is covered; else the barrier from Floater; else Floater; a Floater map with a flip is `Numerical`. Solver failures move to the next map; Cancelled, Timeout and Budget propagate.
12. **Sampling:** "lowest face id" is the lowest id of the local disk (faces in `patch_faces` order, split faces appended), which is deterministic. Grid points on the rectangle boundary are located too, to get their reference normal.
13. **Final check, precise rule.** At corner v of quad (v, a, ..., b): `((a - v) x (b - v)) . n > 0`, where n is the normal of the W' face containing that corner's grid point in its patch map. Then `QuadMesh::validate` (each directed edge once), one fan per vertex, every vertex used, and V - E + F == `TMesh.chi`. The patches with a failing corner are re-meshed with plain Floater (once); a patch that already used Floater, or that still fails, gives `Err(Invariant)`.
14. **vflag:** chain id + 1 of the node's own chain, else the lowest chain of the arcs through the vertex (layout chain ids; the engine renumbers them globally as 8.4 says); bits 20..23 from `chain_kind` when given, else from the ArcKind of the chain's lowest arc (Feature gives Hard; Boundary, Symmetry and Guide map to themselves; GuideHard needs `mesh_patches_with`); bit 24 for FeatureCorner and BoundaryCorner nodes, bit 25 for Cone nodes, bit 26 for vertices on a boundary edge of the quad mesh. `face_comp` is 0 for every quad: the engine sets the component.
15. **Determinism and control:** patches run in parallel (rayon), each sequentially; the first error in patch order is returned. `ctl.check()` runs per patch, per grid row, every 64 BiCGSTAB iterations, every 16 Gauss-Seidel sweeps and every barrier iteration. Bit-identical output for 1, 4 and 8 threads (tested).
16. **Dependencies:** `robust` was dropped (exact predicates come through `aq_core::exact`), and the unused dev-dependencies `aq_testkit` and `aq_io` were removed; Cargo updated the aq_patch entry of `Cargo.lock`. aq_layout is not available yet, so the tests build layouts in `tests/common`: axis-aligned rectangle dissections of a uv domain, triangulated on a jittered grid (random or forced diagonals), lifted to 3D by any map, with exact T-mesh extraction, plus a QComb builder using aq_quantize's union-find rules.
17. **Tests, interpretations** (`crates/aq_patch/tests/patch.rs` and a unit test of the zero-arc intervals; 0.4 s in release, 6 s in debug):
    - Hemisphere disk patch: the square [0, 8]^2 mapped by the elliptical square-to-disk map onto a hemisphere of radius 16/pi (each side a quarter of the equator, length 8), 32 x 32 jittered cells: 64 quads, 81 vertices, every corner Jacobian positive, 32 boundary vertices within 1e-9 of the W' polylines. Same result (within 1e-9) with part of the patch in another chart (transitions inside the patch).
    - Floater: 1000 random star-shaped disks (1 to 6 jittered rings, 8 to 40 boundary vertices, random diagonals and heights), boundary on a circle or on a square with collinear sides: 0 flips.
    - Barrier: 200 random disks with twisted anisotropic targets and a folded initial map (interior vertices scattered): 0 flips, energies strictly decreasing, fixed vertices unchanged, at least 190 runs decrease the energy. In the pipeline, a seamless uv twisted by 4 rad about the patch center folds the least squares map and ends with the barrier map; a wide 2.5 rad twist gives an injective least squares map whose quads fail the final check, and the patch is re-meshed with Floater.
    - Zero arc and zero-height patch: a 4 x 0.25 patch quantized to height 0 between two patches, and two T-offset cases (the zero arc ending and starting the sides it lies on): 16 quads, 25 vertices, exactly 40 edges each; the merged vertex is the average of its two nodes.
    - T-junction (an 8 x 2 patch with a 4 x 4 patch on half of its top side): 32 quads, 47 vertices, manifold, no duplicate positions.
    - Shared arc samples: two patches on a cylinder; the shared column is bitwise equal in both grids, in the arc samples and in the mesh, and lies at `j len / n` on the polyline.
    - Boundary-only triangles: a hand-built disk with an ear whose 3 vertices lie on side 0 (Floater folds it without the split, not with it), a 2 x 2 patch with 4 ears, and a strip one cell thick.
    - Cylinder patch (6.375 x 4.375 on radius 3, quantized to 6 x 4): field-aligned, mean corner deviation below 3 degrees.
    - Performance: 4900 quads from 96800 W' faces (100 patches) in about 0.04 s in release on this machine (budget 1.5 s); skipped in debug builds.
18. **Note for the integrator:** the final check can reject an injective field-aligned map when the seamless param is strongly twisted inside a patch (the sampled quads are then non-convex in 3D). The Floater re-mesh fixes it and `PatchReport::remeshed` counts it, so a high `remeshed` count flags a poor S7 param.

### WP-10 (aq_param), 2026-10-29

1. **`seamless(px: &ProxyRef, ...)` takes a borrowed view, not `&Proxy`.** `Proxy` lives in aq_prep and aq_param depends on aq_core, aq_linalg, rayon and robust only. `aq_param::ProxyRef { mesh, topo, frames, feats }` is field-for-field the view requested by WP-09 (see "Core change requests"). The rest of the DESIGN 6.9 signature is unchanged.
2. **API additions:** `seamless_detailed` (also returns `ParamDiag { loop_set, e1, e2, fold_history, kept_folds, repair: RepairStats, uv_float, n_pred_snapped, n_c }`), `prepare` (one solve for an explicit loop selection, scaled to the count, with no guard, stiffening, repair or snap; used by the repair test), `pub mod repair` (`repair`, `RepairInput`, `RepairStats`), `loop_holonomy`, `face_dets`, `LoopSet { None, Rings, All }`. `ParamParams` gains **`loop_guard` (default 1.3)**, the guard factor of the loop step, so a caller (and the twisted torus test) can force or forbid loops. A loop set is kept when `E <= loop_guard * E0 + 1e-9 * area` (the slack stops rounding from dropping loops that analytic inputs satisfy exactly). At most 3 analyses; with no nonempty loop row there is a single solve.
3. **`n_target <= 0` (the default) uses `SizeField::predicted_count`** as the target count. `report.n_pred` is the count of the float uv after scaling and before the snap (equal to the target within 1e-9); `ParamDiag::n_pred_snapped` is the count after the snap. `report.e_final` is the unit-weight energy of the final float uv; `report.scale` is nu.
4. **Rows are divided by the gcd of their coefficients before elimination.** On genus 0 the closure row of the last cone can become `2 x = 2 c` (or carry a larger common factor) after substitution. That row has no unit pivot, became a penalty row and broke exactness on the cube sphere. DESIGN says only the +-2 parity case arises, which is wrong: +-1 cones produce it too. After the division every such row has a unit pivot, and the right side stays integral because it carries the same symbolic factor.
5. **Pivot preference:** closure rows pivot on the highest translation id (translation variables first), chain iso rows on vertex variables first. This keeps the translations free and the free set small. Any choice gives the same solution up to the gauge.
6. **Closure rows** are written for every interior vertex whose fan crosses the cut, not only at cut-graph nodes. The extra rows are redundant and counted in `report.redundant`. Boundary fans are walked from their lowest face in both directions (forward with `T(prev)`, backward with `T(fan[i])`).
7. **Guide chains get no iso rows and `he_family = FAMILY_NONE` in M1.** DESIGN makes them soft, and the M1 energy has no soft term. Hard, GuideHard, Boundary and Symmetry chains get iso rows. `he_family` of a twin is `fam ^ (r & 1)`.
8. **Free variables used by no corner and no translation are pinned to 0** (otherwise the solve is singular). The gauge pins the lowest vertex of every component.
9. **Penalty rows** (rows left without a unit pivot) are weighted by `penalty_w * mean diag` of the energy part, so `penalty_w` is relative and scale free. On a Numerical factorization the solver retries once with `1e-10 * mean diag` added to the diagonal before giving up.
10. **Stiffening:** per face `d = |s1 h - 1| + |s2 h - 1|`, plus 10 on a folded face (15 if not finite), and `w += min(d, 5)`. The new weights are then averaged once over each face and its edge neighbours (Jacobi) to smooth the jumps, and clamped with `tol::clamp_weight` around their mean. After that the solver refactors, rescales to the count and keeps the best solve (strictly fewer folds). It stops at 0 folds or when the count does not decrease. `kept_folds` is the running minimum of `fold_history`.
11. **Repair details:** a face is folded when `det <= fold_eps(dets)` (the global eps of `aq_core::cross::fold_eps`). Regions are edge-connected fold sets grown by 2 vertex rings. A region is accepted only if it is a disk (V - E + F = 1, one boundary loop). A region with an interior cone (index4 != 0), or whose unfolding through the transitions is inconsistent, is skipped (`skipped_cone`) and its folds stay, as M1 specifies. A vertex is movable when it is interior to the region and its two rep free variables are shared with no other vertex. Vertices on cut arcs, chains or pins therefore stay fixed, which is stricter than "only rep x variables". The boundary polygon simplicity test uses exact orient2d. Floater MVC is solved with a dense LU (regions capped at 1000 vertices and 20000 faces). The barrier is the 6.12 local-global scheme with a Cholesky factor of the region Laplacian. Its steps are bounded by 0.8 of the first det root, with backtracking until the energy strictly decreases (instead of Armijo), for at most 10 iterations. A region that fails, or fails to verify after write-back, is reverted bitwise.
12. **Exact output:** free values are rounded to integer multiples of `2^-24` (i64), and corners and translations are evaluated in i128 from the integer expressions, then converted. |uv| must stay below 2^27 and |t| below 2^28 (`Numerical` otherwise). Side A of each arc gets `(arc.r, t_a)`, side B its inverse. After the snap, `SeamlessParam::validate` runs and every exact loop is checked to close bitwise (`Invariant` otherwise).
13. **Tests, interpretations** (`tests/param.rs` with 11 tests, `tests/robust.rs` with 4, plus 2 unit tests; about 2 s in release and 35 s in debug):
    - Plane: exact (error 0, not just < 1e-9), because the testkit's expected uv is dyadic.
    - Torus 5% gradient test: on a fat torus `|grad u|` varies like `1/(R + r cos psi)` by construction of the M1 energy, so the test uses a slender torus (R/r = 25, 100 x 4 cells), where 95% of the faces are within 5%.
    - Twisted torus: the default guard drops the loops (the energy grows by more than 1.3x). The "with loops" half sets `loop_guard = INFINITY` and gets `tau_perp == 0` exactly. The control has `|tau_perp| > 0.05` for every loop.
    - Stiffening uses a plane field rotating with `k x y / 10` (k = 1, 2, 3; many cones), where the first solve folds. The kept folds are the running minimum and never increase.
    - Repair: 10 vertices near the centre of the 24 x 24 plane param are perturbed by 0.9 cell. There are 0 folds after the repair, and every other vertex and every corner of a face outside the regions is bitwise unchanged.
    - Gauge invariance: a double torus (genus 2) with a smooth field (300 Jacobi smoothing iterations of the power field) and a random vertex permutation. Faces and halfedges are kept, so the field and the cut carry over. The float uv is equal up to one translation within 1e-8, and the rotations of the transitions are equal. The translations are not compared, since they change by `c - R c` under a global shift c. The snapped uv is compared within 1e-6 instead of 1e-8: each corner sums several free values rounded to the 2^-24 quantum (6e-8), and the two eliminations choose different expressions.
    - Performance: a cube sphere with 99372 faces runs in about 1.5 s in release on this machine (budget 5 s). The test is skipped in debug builds.
14. **Determinism:** assembly, solves and repair regions run sequentially in a fixed order. `rayon` stays a dependency but is unused in M1. Bit-identical output on another thread is tested.
15. **Note for the integrator:** the M1 repair leaves folds next to cones (`skipped_cone`), so `folds_after_repair` can be nonzero on fields with many close cones (the rotating plane field keeps 6 to 20 folds). S8 should treat `SeamlessParam::folded` faces as untrusted.

### WP-11 (aq_layout), 2026-10-29

1. **`build_layout(px: &ProxyView, ...)` takes a borrowed view, not `&Proxy`.** `Proxy` lives in aq_prep, which aq_layout does not depend on. `aq_layout::ProxyView { mesh, topo, feats }` holds the three parts S8 reads (no frames). The rest of the DESIGN 6.10 signature is unchanged (see "Core change requests").
2. **API types.** The design's `ConstraintCurve`, `Trace` and `CurveRef` are one type, `Curve { kind: CurveKind, chain, src, pieces: Vec<Piece>, closed }`, with `CurveKind { Chain, Loop, Separatrix, SeedTrace }`. A chain curve has no pieces (its edges are proxy edges). A `Piece` is the part of a curve inside one face: `Line { d, c }` (travel direction code 0 +u, 1 +v, 2 -u, 3 -v and the dyadic transverse constant) plus start and end `Pt { V(corner), E(edge), X(value) }`, the entry and exit edges, an on-edge flag and the time at its start. `Emitter { vert, face, dir, kind }` and `Seed { vert, face, dir }` give a ray in the chart of `face` (`dir = 255`: every free axis). `trace_all(px, prm, curves: &[Curve], emitters, p, ctl) -> Result<Vec<Curve>, LayoutIssue>`, `embed(px, prm, curves: &[Curve]) -> Result<Embedded, AqError>` and `extract(e, px, prm, hints: &[NodeHint]) -> Result<Layout, LayoutIssue>`: extract also needs the param (cone indices) and the node hints (cones, corners, chain ends, seeds; built by `node_hints`). Additions: `build_layout_with` (initial seeds, returns `LayoutStats { runs, seeds, n_loops, n_traces, n_events, n_voided }`), `curves::constraint_curves`, `curves::emitters_for`, `pub mod geom` (the exact iso-line predicates).
3. **SoS.** The perturbation is an infinitesimal to the left of the travel direction. Rotations preserve "left", so it needs no bookkeeping through the transitions (the design's "transverse orientation carried by R" is the same rule written per trace). A corner on the exact line is on the right side, and a line through a vertex sweeps the faces of its left half fan with zero-length pieces. Two opposite traces on the same line therefore pass a vertex through different faces, and along a mesh edge they lie in the two different faces of that edge. Head-on detection uses the shared faces, plus a per-edge registry of on-edge pieces.
4. **Event engine (deviation from "no deeper rollback").** A trace places its whole chord when it enters a face, so a placed chord runs ahead of the simulation time. The design's claim that truncating the owner of S needs no deeper rollback is false: the removed part of the chord may already have decided another collision (a third trace was told to stop on it). Every collision therefore becomes a `Stop` event at the loser's arrival time, and the event is validated when it is popped. The other curve must still cover the point; otherwise the stop is void and the trace goes on (`LayoutStats::n_voided` counts them, and the perturbed cube spheres do void some). Truncation keeps the pieces up to the stop point. Head-on: both stop where their times are equal, snapped to 2^-24 and clamped exactly into the overlap. If the other trace dies first, the trace stops at the other's dead end (a join). Equal times: the higher id stops. Same-direction overlap of two traces (never seen in practice): the follower stops at the overlap start.
5. **Stop vertices:** cones, vertices of constraint chains, boundary vertices, vertices an exact loop passes through, and every emitter vertex (seeds included). A trace stops when it reaches one, and when it crosses a constraint chain edge.
6. **Emission.** Interior cones emit every free axis ray, and the check is that the number of axis rays at the cone equals `4 - index4` (occupied rays included). Chain corners, cones on chains and open constraint chain ends use the minimal rule: inside each sector between consecutive occupied rays, rays at quarter-turn offsets 2, 4, ... (strictly inside). A 90 degree corner gives 0 rays and a 270 degree corner 1 (offset 2, the continuation of the other side). An open Hard chain end gives 1 continuation ray already in M1 (DESIGN lists open ends only under the M2 guides; without it the dangling arc only produces a seed round). A folded or degenerate face at an emitter vertex returns `Invariant`.
7. **Exact loops.** The axis comes from the holonomy of the LoopCand dual path (composed transitions). It must have R = identity and exactly one nonzero translation component, otherwise the loop is skipped. The loop is traced in one direction, since it is closed (tracing both directions is redundant), until it re-enters its start face on the same line through the same edge. It is dropped on the boundary, beyond `max_trace_len`, or when its line duplicates an earlier loop. Loops cross each other and chains freely.
8. **Embedding.** Cells are cut by an exact planar graph per face (axis or edge-vector directions, exact angular sort) and triangulated by ear clipping on combinatorially strict corners, with no Steiner points. This replaces the design's fan triangulation, which makes zero-area triangles at T-junctions. W' uv of an edge point: the iso coordinate is exact and the other coordinate is snapped to 2^-24 in the canonical chart, then mapped exactly into the twin chart, so `wtrans` holds bitwise. The design gives uv only for 3D interpolation. A degenerate uv face that a curve crosses returns `Numerical`.
9. **Extraction.** Nodes are the hints plus every curve vertex of degree other than 2, or of degree 2 with two different curves, except two traces that both end there (a head-on join is not a node, so the cube sphere has 8 nodes, 12 arcs and 6 patches). Arc length is the sum over W' edges of `max(|du|, |dv|)` (exact for iso edges). Corner counts come from signed uv angle sums over the patch's corner classes (union-find of corners across unlabeled edges). If a count is not an integer within 0.02, the result is `Fatal(Numerical)`. A count-1 occurrence at a non-node, and a side that is not axis-consistent in the patch chart, give `Fatal(Invariant)`. The patch chart is the BFS rotation from the lowest patch face. The wrap flag is set when both end nodes are Regular, `len < 1.5`, and the two nodes share another trace. lb and weight follow the testkit `arc_defaults` with allow_collapse off (S9 decides collapses).
10. **Seeds.** Rule (a): the lowest proxy vertex on the patch boundary whose patch sector spans at least 2 quarter turns. It emits the middle interior ray (perpendicular on a straight chain). Rule (b), when there is none (no boundary, or a boundary made only of new W' vertices, as between two ring loops): the lowest interior non-cone proxy vertex, emitting all 4 axes. The design's "lowest-index node" is not used, because a T-node is a new W' vertex that does not exist in the next run. If a round adds no new seed, the result is `Invariant` at once. `max_rounds` counts re-runs: 1 + `max_rounds` runs, then `Invariant`.
11. **M2 items:** `simplify` and `guide_continuation` are accepted and have no effect. Guide chains are neither constraint curves nor arcs in M1. Runaway gives `ErrKind::Infeasible`, and every error is stamped `Stage::Layout`.
12. **Tests** (`tests/layout.rs` with 14, `tests/motorcycle.rs` with 5, 3 unit tests; about 2 s in release):
    - Planar square for (alpha, s) = (0, 1), (0.37, 2), (-1.1, 0.5): 1 patch, 4 BoundaryCorner nodes, arc lengths 8 within 1e-12. A forced seed gives 4 patches, jittered and grid-aligned.
    - cube_sphere_param n = 2, 3, 4 and n = 3 res 2 (separatrices along mesh edges): 6 patches, 8 cones, 12 arcs of length exactly n.
    - perturbed_cube_sphere_param: 20 seeds at n = 4, amp 0.3, plus 4 seeds at n = 6, amp 0.4. Every arc lies on 2 sides, V - E + F = 2, patch areas sum to the mesh area within 1e-9, and health max < 1e-6.
    - Torus with exact loops: n m patches, with rings. Bare torus: 1 seed round (rule b). Open cylinder: 1 patch after 1 seed round (rule a). Cylinder with loops: valid.
    - Grid-aligned variants: plane, torus, cylinder and cube sphere at res 1 to 3. They are valid, have no duplicate W' positions, and are deterministic.
    - The hand-built motorcycle instance uses explicit emitters on the aligned 16 x 16 plane instead of a crafted 2-cone param. The later trace stops, a stopped trace does not block a third one, equal times stop the higher id, and head-ons meet at a vertex, at an edge midpoint, and at 7.5 on a 15 side. A jittered grid case checks that a placed chord is truncated inside a face.
    - W' quality: manifold, inherited transitions bitwise exact and inverse on twins, positive uv orientation, and children areas equal to the parent face area within 1e-9.

### WP-08 (aq_field), 2026-10-29

1. **`solve_field`, `knoppel`, `edit_path` and `resolve_fixed_matching` take `px: &ProxyRef`, not `&Proxy`** (`Proxy` is an aq_prep type; aq_field depends on aq_core and aq_linalg only, 3.2). `aq_field::ProxyRef { mesh, topo, frames, feats }` is field for field the view of WP-09 and WP-07; the engine builds it with `ProxyRef::new(&px.mesh, &px.topo, &px.frames, &px.feats)`.

2. **Hard faces end exactly on their constraint edge, not on the smoothed tangent (deviation, required by C9).** The segment-smoothed tangent psi of 6.6 step 1 is the Knoppel constraint value (`z_f = exp(4i psi_f)`), as specified. After the solve, every hard face is snapped to the branch of its **own constraint edge** direction nearest the Knoppel angle, and the re-solves keep it there. Reason: the boundary index of C9 is an integer (residual < 1e-6) only when the field in the first and last face of every boundary fan is aligned with that face's boundary edge; a tangent smoothed over neighbouring edges is off by a fraction of the per-edge turning (about pi/n on a circle of n edges), so `index4_all` returns `Invariant`. This is the same snap aq_testkit applies (WP-01b item 4). Interior Hard / GuideHard chains (hard_mode 2) get the same treatment, so S7 receives fields exactly on the chain iso-lines. The window is 0.5h long, centred on the edge midpoint, weighted by overlap length, stops at segment corners and chain ends, and sums the chain edge vectors projected into the face plane. The test "constrained faces exact (1e-12)" holds on the planar square and the cube.

3. **Faces with several constraint edges:** boundary first, then Symmetry, then the others, lowest k on a tie. The other constraint edges must be orthogonal to the chosen one within 1e-9 (square and cube corners), otherwise `Invariant` ("feature isolation must run before S4"), because no direction can be aligned with both.

4. **hard_mode:** Boundary and Symmetry edges are always hard. Hard and GuideHard are hard for hard_mode 2, soft guides for hard_mode 1, ignored for hard_mode 0 (aq_prep already rewrites them, this only makes S4 safe on its own).

5. **Guides (M1 soft alignment, 11.1):** faces with a Guide edge (and Hard / GuideHard edges in hard_mode 1) take the smoothed guide tangent as a target; faces within 0.5h (dual Dijkstra over face centroids, never through hard faces) inherit it, transported with kappa. Weight `20 guide_w / h_f^2 * A_f` (conf 1), added to the curvature term in both the Knoppel solve and the re-solves. Untested beyond Poincare-Hopf; the guide gate is WP-21's.

6. **Eigen path (deviation: normalized iterations added).** A component takes it when it has no hard face, no guide face, and `align = 0` or an area-weighted mean conf below 0.01. The shift is `1e-8 * mean diagonal` scaled by `A_f / mean A` (a mass shift, so the eigenvectors are those of `H x = mu M x`), the start is uniform in [-1, 1]^2 per face from `SplitMix64(seed)`, and the 8 linear iterations are mass-normalized as specified. **Then at most 16 normalized iterations `x <- A^-1 M (x / |x|)` follow on the same factorization** (stop when the mass-norm change is below 0.01). Reason: on round shapes the lowest eigenspace is degenerate (on a sphere the spin-4, l = 4 space is 9-dimensional), so the linear iteration returns an arbitrary member: the closest cone pair was measured 0.36R to 0.96R apart over 60 runs (icosphere levels 3 to 5, 20 seeds each), and the 6.6 test asks for at least 0.85R. Normalizing per face and projecting again selects the member of most uniform magnitude, a Ginzburg-Landau type step that repels same-sign cones: 0.93R to 1.21R with this budget (0.99R or more with a fixed 24, at twice the cost; tolerance 0.03 degraded the spread to 0.86R). This acts only inside the eigen path; it is not the MBO sharpening rejected in 1.2 (that one targets angular accuracy of the general solve). The non-degenerate components are solved together in one linear system.

7. **Step order: split, push-off, then cancellation (deviation from the listing order 5, 6).** The run is: split (step 3), re-solve; push-off (step 6), re-solve, split again if the push-off created a high index, re-solve; cancellation rounds (step 5), each with its re-solves; final re-solve. Reason: paths never touch chain vertices, so a cone sitting on a chain cannot be cancelled before it is pushed off; and a cancellation only removes cones, so it cannot undo the push-off's clearance. Push-off details: one quarter at a time, along the shortest restricted path to the nearest non-chain interior vertex at least 0.75h (its own h) from every chain that is not a cone of the same sign, searched within 20h. "Chains" include the boundary; Symmetry boundary edges count as Symmetry. Corner vertices are never moved.

8. **Revert, precise rule.** A round applies its selected pairs one after the other, each on a shortest path found in the current state, then re-solves. Pairs whose path has an edge with |delta| > pi/3 are reverted by restoring the state from before the round and re-applying the kept pairs (then re-solving, repeated until every kept path passes). In p this is exactly the opposite edit (edits add mod 4); it avoids applying an opposite edit to an edge whose re-solved delta exceeds pi/2, which would carry the residual past pi and break the stored delta (WP-00 item 2). A reverted pair is not retried in later rounds.

9. **Edit safety:** every edit made by S4 uses an edge only while `|delta - s pi/2| < 0.8 pi`, so the residual stays inside (-pi, pi) and the incremental index update equals `index4_all` (tested). `edit_path` (DESIGN signature) leaves the field unchanged on an invalid path; `try_edit_path` returns `InvalidInput` (vertex out of range, no halfedge, boundary edge). Any i8 s is accepted (s mod 4 on p, s on the index).

10. **Details DESIGN leaves open:** geodesic distances are Dijkstra over Euclidean edge lengths, ties to the lowest vertex id. `hbar` is the mean of `h_vert` at the two cones. The low-confidence disc is the set of faces touching the vertices within d of the path midpoint (the first path vertex at distance >= d/2). The split target w is the non-chain interior neighbour, reachable through an edge that passes item 9, with the largest distance to the other cones (lowest id on a tie). The split also applies to non-corner chain vertices that are interior; non-corner boundary cones are handled by the push-off. The re-solve lifts each edge residual by the multiple of 2pi that makes the current residual equal the current delta; its matrix depends only on the weights and the fixed faces, so `solve_field` factors it once for all its re-solves (`resolve_fixed_matching` factors its own). A component with no hard face and no alignment pins its lowest face.

11. **API additions:** `edit_singularities(px, c, s, &mut CrossField, p, ctl) -> FieldReport` (steps 3 to 7 on any field, used by the planted tests), `try_edit_path`, `field_energy(px, c, s, f, p)` (the step 7 energy, hard faces excluded from the alignment sum), `FieldParams::default()` (DESIGN 13: align 1, guide_w 1, hard_mode 2, cancel 1.2 / 2.5, 3 rounds, sym 0.5, size_consistency 0, seed 0), constants `CHAIN_CLEARANCE`, `PUSH_TARGET`, `MAX_EDIT_DELTA`, `LOW_CONF`, `EIGEN_CONF`. `FieldReport.cones_initial` / `cones_final` count every vertex with index4 != 0 (boundary corners included); `split` and `pushed` count quarter moves. `solve_field` and `edit_singularities` validate their result (CrossField::validate with Poincare-Hopf, interior non-corner |index4| <= 1, hard faces within 1e-9 of their edge). ### WP-08 review follow-up (aq_field), 2026-10-29

This entry supersedes the "Noise robustness" line of WP-08 item 13: that test used a near-isotropic blob (mean conf about 0.0006), so it took the eigen path with alignment off and could not fail. Measured on the old code with a test that can fail: testdata noisy_blob gave 108 cones with align 1 against 12 with align 0, and a lumpy blob with real curvature anisotropy gave 34 clean and 40 to 78 noisy.

1. **Coherence filter of the curvature target (deviation from 6.6 step 2).** DESIGN uses `lambda_f A_f conf_f |z_f - q_f|^2` with `q_f = exp(4i phi_f)`. aq_field now first smooths `conf_f exp(4i phi_f)` once by implicit diffusion with the 4-connection, `(M + L_t) qs = M q`. L_t uses the weights `t_e w_e`, with `t_e = (1.5 h_f)(1.5 h_g)`, and is solved by Jacobi PCG from q to a relative residual of 1e-3 (about 80 products, 0.2 s at 82k faces, where Cholesky took 0.6 s; serial and deterministic). The alignment then uses `conf'_f = conf_f * min(1, |qs_f| / conf_f)^2` and the target `arg(qs_f) / 4` (phi_f where qs vanishes). The Knoppel solve, the step 7 re-solves (phihat) and the low-confidence disc of step 5 all use them. Reason: curvature noise passes the conf gate (noisy_blob has mean conf 0.225, against 0.114 on the clean lumpy blob), but its directions are incoherent at the quad scale, so the average collapses. Coherent directions (cylinders, tori, smooth lumps) keep their weight: the cylinder and torus fields still lie within 2 degrees on 100% of faces. Radius 1.0 and 2.0 and exponent 1 and 3 were also measured; 1.5 and 2 was the best compromise. The eigen path decision (mean conf < 0.01) still uses the raw conf, as DESIGN says. The filter runs only when some component takes the linear solve.

2. **Normalized iterations of the aligned solve (deviation from 6.6 step 2, same idea as WP-08 item 6).** After the linear Knoppel solve, at most 16 iterations `H z_{k+1} = b + mu M z_k / |z_k|` run on the same factorization (one triangular solve each), with `mu_f = 0.2 A_f / h_f^2`, the weight of a conf 0.2 face at align 1. Reason: the linear power field shrinks |z| towards 0 wherever alignment is weak or incoherent, and every such dip becomes a cone (the old code made 210 initial cones on noisy_blob). Feeding back the unit field keeps |z| uniform there, so the field follows its smoothest continuation as on the eigen path, while strongly aligned regions are unchanged. Measured (mu, iterations) on noisy_blob: (0.05, 8) 26 cones, (0.2, 4) 26, (0.2, 8) 18, (0.2, 16) 14, (1, 8) 18. A larger mu weakens real curvature alignment. 2. **Sliver pass (addition to the DESIGN 6.4 iteration, after smoothing).** Faces with a minimum angle below 2 degrees, smallest first, in up to 6 rounds. Per face, in order: (1) flip the edge opposite the largest angle when that raises the minimum angle of the two faces (never a chain or boundary edge; valence is ignored, but a and b keep at least valence 3; no new face may fold against the area-weighted normal of the two faces and their four neighbours; the 30 degree rule of item 4); (2) collapse the shortest edge with relaxed rules: new edges up to 5/3 len, every new face must beat the smallest angle of the old neighbourhood (so the local minimum strictly rises), and an old face below 2 degrees is compared with the neighbourhood's area-weighted normal for the 60 degree rule instead of its own unstable normal (chain, corner and link rules unchanged); (3) for a cap (largest angle above 120 degrees) with a free apex, split the opposite edge at the foot of the apex (on the chain polyline for a chain edge) and collapse the apex into the new vertex, else undo the split. ### WP-16 round 3 (aq_param, aq_engine; M1 tuning), 2026-10-30

1. **Foldover-free untangler in the S7 repair (`aq_param/src/repair.rs`, `foldover_free`).** This is more of the M2 cone-aware repair (WP-24), pulled forward. Root cause of the basemesh_female S8 failure ("cone of index4 -1 has 1 axis rays instead of 5"): at the crotch saddle, the S7 repair left -1 cones whose fans wound 90 degrees instead of 450, and stars mirrored (vertex uv angle sum -360 degrees). The kernel sweeps start from that configuration and cannot leave it, and Floater only runs on regions of at most 400 movable vertices.
   - `foldover_free` minimizes the regularized untangling energy of Garanzha et al. 2021 ("Foldover-free maps in 50 lines of code") over the movable vertices: L-BFGS (history 8), Armijo backtracking, and their epsilon schedule. Constants: `FF_LAMBDA` 1, `FF_ROUNDS` 30, `FF_MIN_ROUNDS` 4, `FF_ITERS` 50. It is accepted only when every det is above eps.
   - `cone_region` now runs, in order: Floater (only with at most `MAX_CONE_REGION_VERTS` 400 movable vertices) then kernel sweeps; else kernel sweeps from the current solution; else `foldover_free` from the current solution, up to 2 attempts. Between attempts the link of every wrong-wound cone is reset at equal angles (want / valence) with the mean 3D spoke length as radius. Otherwise the region grows. The movable cap for this path is `MAX_FF_REGION_VERTS` 4000.
   - `try_region` (regions without cones): when Floater leaves folds, the positions are restored and `foldover_free` runs before growing. Unknowns are ordered by lowest outgoing halfedge, as before, so a vertex permutation runs the same arithmetic.

### WP-20 thickness cap (M2), 2026-10-30

Scope: the thickness cap of DESIGN 6.5 (M2) in aq_curv, a global plan across components in aq_engine, and one debris rule change. No change to aq_core, aq_prep or aq_field. Results, renders and the gate table: `eval/M2_THIN.md`.

1. **Shape diameter (`aq_curv/src/thick.rs`, new).** d(v) from 5 rays per vertex: one along -n_v and 4 at 15 degrees from it (a 30 degree cone, read as its full angle), each the first hit of a **back face** (dot(ray, n_f) > 0) through an own BVH (`RayBvh`: median split, slab test, Moller-Trumbore), skipping the vertex's own fan. Deviations from the one-line spec:
   - **Majority of hits:** d is the median of the hits only when at least 3 of the 5 rays hit a back face, else infinity (no cap). With fewer hits the median is one stray ray through a gap.
   - **Ray length bound:** rays stop at 10 h (`THICK_D_MAX`); a diameter above that never caps (`pi d / ring_min` would be above 3.9 h for ring_min 8, above G_MAX anyway). This keeps a big closed mesh at about 100 ms.
   - **1-ring median filter** on d, against single bad rays at creases.
   - **Plate filter (`plate_filter`).** The cap `pi d / ring_min` assumes a round cross-section. On a thin **plate** (a solidified cloth shell, a slab) d is the plate thickness but its cross-section is as wide as the plate, so the pure cap asked for quads of a fraction of h over whole sweaters. A vertex keeps its d only when some vertex within geodesic distance d (Dijkstra over mesh edges) has a normal turned by more than 60 degrees from its own (`TURN_COS` 0.5): tubes (the normal turns by about 115 degrees within d) and plate rims keep it, plate interiors get infinity, and the gradation spreads the rim size inward. Test `plate_interior_is_free_and_rim_is_thin`.
2. **Thickness cap in the sizing (`aq_curv/src/sizing.rs`).** `h <= max(pi d / ring_min, floor)`, combined with the tube cap by min, before gradation and normalization (so the count stays exact). Deviation: **a budget floor** instead of the bare `pi d / ring_min`. On retopo_a and retopo_c the bare cap spends 30 to 60% of N on thin rims and strands, which empties the rest of the mesh and drives edge CV up (0.23 to 0.6). The floor is the smallest value >= G_MIN for which the caps spend at most `thick_budget * N` quads beyond the field without them (`thickness_floor`, an estimate without gradation, bisection on ln f), and never below `thick_floor_min` h. A floor trims the thinnest parts first, which gives the smallest edge length spread for a budget. Defaults: `THICK_BUDGET` 0.1, `THICK_FLOOR_MIN` 0.7 (0.5 gave retopo_c CV 0.225 against 0.20). New `SizingParams` fields `thick_budget`, `thick_floor` (a lower bound of the floor from the engine), `thick_floor_min`; `SizingParams::new` keeps `thickness: false` so M1 callers are unchanged. New `SizingReport` fields `thick_verts`, `thick_capped`, `thick_floor`, `thick_share`, `thick_ms`; `thickness_skipped` is now always false. `sizing_diam` takes precomputed diameters (`curvature_and_sizing` measures d once for both passes).
